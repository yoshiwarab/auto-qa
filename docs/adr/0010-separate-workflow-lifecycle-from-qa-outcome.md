# Separate workflow lifecycle from QA outcome

A Run that finishes its workflow enters `completed` even when it discovers defects, with a separate Run Outcome of `passed`, `defects-found`, or `inconclusive`. Unresolved Confirmed Defects take precedence over inconclusive coverage, which takes precedence over passed. When a Run has both an unresolved Confirmed Defect and exhausted or skipped coverage, its Outcome is `defects-found` with `coverageIncomplete: true` and the incomplete Scenarios listed explicitly. A historical Confirmed Defect that was repaired through an authorized `fix-application` Job does not remain sticky: when every latest required Attempt passes, the Run Outcome is `passed` while the Finding, fix authorization, and prior Attempts remain visible in history. The terminal `failed` phase is reserved for an unrecoverable Auto-QA failure, while `blocked` remains an input boundary for required external action.

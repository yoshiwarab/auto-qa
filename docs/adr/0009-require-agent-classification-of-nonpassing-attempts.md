# Require agent classification of Attempt Findings

Auto-QA will not infer an application defect directly from an Attempt's mechanical status, and it will not accept a mechanical pass without agent judgment of the resulting evidence. After an execution batch, every Attempt contributes one Finding to a single atomic `classify-findings` Job. A mechanically passing success Finding may become `verified-success`, while any Finding may be classified `app-defect`, `likely-defect`, `observation`, `test-issue`, or `infra-issue` as allowed by its cause; `verified-success` is invalid for a mechanically nonpassing Attempt. `app-defect` becomes a Confirmed Defect, `test-issue` requests a bounded replacement Scenario Script, and `infra-issue` may request explicit rather than silent rerun. `interrupted` remains an Attempt status and Finding cause, not an agent classification; its next action is an explicit rerun or an inconclusive report. Classification never rewrites the stored mechanical Attempt status.
